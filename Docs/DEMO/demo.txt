PART B: TARGET LLM USAGE AT 6.5M SCALE

Roles:
1. Ownership inference (classification): map queues/channels to owning app where metadata is missing or conflicting. Unit = distinct naming-pattern cluster (deterministic tokenisation), not row. Cache by signature hash.
2. Queue purpose/criticality classification (classification): payment/PCI, batch, request-reply, pub-sub, dead/test. Inputs: name tokens, attributes (DEFPSIST, MAXDEPTH, TRIGGER, USAGE), connected apps. Unit = distinct queue signature.
3. Anomaly triage (reasoning + classification): deterministic detectors emit candidates (orphans, zero-traffic, cycles, stale channels, non-standard attributes). LLM labels each retire / migrate / investigate with evidence. Unit = candidate.
4. Community architecture review (reasoning): one call per community, chunked. Hierarchical map-reduce: community → domain → enterprise summary. No truncation; if a community exceeds the budget, split it.
5. Migration wave reasoning (reasoning): the deterministic dependency solver produces feasible waves; the LLM resolves trade-offs and ties and writes the rationale. The solver re-validates.
6. Config remediation (reasoning): propose target attribute/MQSC deltas for non-standard objects. The validator enforces MQSC syntax and WF policy rules; an invalid proposal is rejected, never auto-applied.
7. Documentation generation: ADRs, wave runbooks, change-record text per wave.
8. Human feedback interpreter and chat: with a hard turn limit and token cap per session.
