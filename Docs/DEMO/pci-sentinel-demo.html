01 · The problem

The catalogue is authoritative — and incomplete.

Cardholder data spreads across thousands of interconnected systems. The Business Application Metadata (BAM) is the system of record, but it under-reports who actually touches PAN. Scoping a PCI DSS audit by hand is slow, opaque, and easy to get wrong — and every system wrongly in or out of scope is either wasted audit cost or unguarded exposure.

Invisible exposure

Systems carrying clear PAN that the catalogue never flagged — undetected audit risk.

No defensible map

Cycles, intermediaries and convergent feeds make "what flows where" impossible to argue line-by-line.

Blind remediation

Tokenize the wrong system and downstream scope barely moves. The leverage points aren't obvious.

02 · How we solved it

Hybrid Intelligence: a verifiable engine, and a language layer that makes it usable.

Two parts with distinct, complementary jobs. A deterministic graph engine produces every measured value — scope, reach, centrality, risk, the tokenization frontier — so the math is always reproducible and auditable. The language model owns the explanation layer: it turns a 4,000-system graph into plain-language lineage and "why-in-scope" reasoning, and powers an interactive Q&A over the grounded results. The engine guarantees the numbers are correct; the language layer makes them usable.

05 · Mathematical rigor

A defensible risk score — every term named, bounded, and cited.

No magic constants. Each system gets a composite risk score on a fixed 0–100 scale, built from four interpretable factors.

R(v) = 100 · ( 0.40·S + 0.30·R + 0.20·B + 0.10·T )
S
Sensitivity tier
PCI data-element class (0–4), normalized.
R
Downstream reach
Systems it can feed, max-scaled to [0,1].
B
Betweenness
Brandes centrality — how much flow routes through it.
T
True-source flag
Originates clear PAN vs merely relays it.

Worked example — the score is fully checkable

system 8MEC
0R(8MEC) = 74.55100
S 0.40×1.000 = 40.0 R 0.30×0.818 = 24.5 B 0.20×0.000 = 0.0 T 0.10×1 = 10.0
Beyond the score

Optimization & structure

Certified-optimal tokenization frontier via branch-and-bound integer programming with a reported greedy optimality gap; network segmentation choke-points via max-flow / min-cut. The full computation is deterministic and reproducible.

Stability check

Weights are structural, not tuned

A weight-sensitivity analysis shows the ranking is driven by the graph itself — re-running with different weights leaves the ordering essentially unchanged (Spearman ρ ≈ 1.00). The result isn't fitted to a desired answer.

Cited foundations
  • Betweenness centrality — Brandes (2001); unbiased sampled estimator at scale — Brandes & Pich (2007)
  • Cycle resolution — Tarjan (1972), strongly-connected components → condensation
  • Segmentation — max-flow / min-cut (Menger's theorem)
  • Data-element sensitivity ordering — PCI DSS

10 · Honest by design

What it claims — and what it does not.

  • It does present current-state PCI lineage from authoritative metadata plus clearly-marked inferred signals, with a reproducible risk model.
  • It does not remediate controls, assert business need, or treat inferred signals as ground truth.
  • Absence of a finding is not proof of a clean system — the signal feeds list observations, not a comprehensive sweep.
  • The engine guarantees the numbers; the language layer makes them legible and answerable — and is structurally prevented from inventing one.

The value is in a defensible map of where cardholder data really flows — and where to cut scope — not in over-claiming. That honesty is the credibility the rest of the system is built on.
