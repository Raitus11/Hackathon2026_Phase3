=== PART 1: Column headers (all grid pages) ===

Current problems: headers are unstyled bare text with no background or separation
from the first data row, they scroll away on long grids, and the drill-hint glyph is
rendering as a stray capital "L" ("CONTROL ID L", "CHECK REFERENCE L",
"UNIQUE CUST ID L") because the character is mis-encoded.

1. Remove the drill-hint glyph entirely. Delete every
   `<span class="drill-hint">...</span>` from all .cshtml files and delete the
   `.drill-hint` rule from site.css. The dotted underline on `.grid-link` already
   signals which columns are drillable — no header marker is needed.
   Confirm no stray literal characters remain in the <th> text.

2. Add a shared `.grid-table` class applied to every data table, with a `thead th`
   rule:
   - background #F5F6F7, color var(--muted), font-size .72rem,
     font-weight 600, letter-spacing .06em, text-transform uppercase
   - padding .6rem .75rem, text-align left, white-space nowrap
   - border-bottom 2px solid var(--line); no top or side borders
   - first-child border-top-left-radius 4px, last-child border-top-right-radius 4px

3. Make the header row sticky: `.grid-table thead th { position: sticky; top: 0;
   z-index: 2; }`. Verify no ancestor of the table has `overflow: hidden` or a
   `transform` that would break sticky — if one does, report it rather than
   silently removing it.

4. Body cells: `.grid-table tbody td { padding: .55rem .75rem; font-size: .85rem;
   color: var(--ink); border-bottom: 1px solid var(--line); vertical-align: middle; }`
   Row hover background #FAFAFA. Remove any zebra striping so the hover state reads
   clearly.

5. Right-align numeric/amount columns (CURR_BAL, TOT_BAL, INSURED_AMT, Accrued
   Interest and similar) via a `.num` class on both the th and td, with
   `font-variant-numeric: tabular-nums`.

6. Apply identical header treatment to the SQL Editor and Trino SQL Editor results
   grids so all grids in the app match.

=== PART 2: Trino SQL Editor page (TrinoSqlEditor.cshtml) ===

7. The results table renders its column header row twice (two identical rows of
   UNIQUE_CUST_ID (VARCHAR), CUST_GOVT_ID (VARCHAR), ...). Diagnose and fix the root
   cause — likely one of: DataTables being initialized on a table that already has a
   server-rendered <thead>, DataTables initialized twice on the same element, or a
   cloned header from a scroll/fixed-header option. Do not mask it with
   `display: none` on the second row. Guard against re-initialization
   (`if (!$.fn.DataTable.isDataTable(selector))`) and ensure the header markup is
   emitted exactly once by the Razor page.

8. The "Search:" box and the "25 entries per page" selector are rendering below /
   overlapping the results table instead of above it. Fix the DataTables layout so
   the controls row sits above the table: length selector left, search box right, on
   one line with align-items: center and 1rem bottom margin. Use the DataTables
   `layout` (or `dom`) option rather than repositioning with absolute CSS.

9. Style those controls to match the app: inputs and selects with 1px solid
   var(--line), 3px radius, .4rem .6rem padding, .85rem font-size, and a
   :focus-visible outline 2px var(--wf-red) offset 2px. Remove the default blue
   focus glow.

10. The type annotations in the headers ("(VARCHAR)", "(DECIMAL(14,2))") should
    render as a separate `<span class="col-type">` on its own line beneath the column
    name: .65rem, var(--muted), text-transform none, letter-spacing normal,
    font-weight 400.

11. Move the query metadata line (Rows / Columns / Time / State / QueryId) into a
    bordered strip directly above the Results heading: .78rem, var(--muted), with the
    State value in var(--ok) when FINISHED and var(--danger) when FAILED. Currently
    it floats unanchored at the right edge.
